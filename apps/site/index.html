The household cash book for two, on your own server.

Livro-caixa keeps a couple’s income and expenses, marks the bills you split with your partner and works out what they owe you at the end of each month. It runs as one Docker container, and the data never leaves your instance.

What it keeps track of

The app speaks Brazilian Portuguese and works in reais. Each part below carries its name in the app, so you will recognise it on screen.

Lançamentos Entries

Every receita (income), despesa (expense) and acerto (settlement) in one book. Each entry is previsto (pending) until you mark it confirmado, so the month shows both what happened and what is still due.

  • Browse one month with its totals, or switch to Todos to search every entry by period and category.
  • Filter by type and status, search descriptions and notes, sort by date, description or amount.
  • Categories are yours to edit in Configurações.

Contas divididas and acerto Split bills and settlement

Mark an expense as dividida and it counts toward your partner’s share, at the split you set (50/50 by default, in steps of 5%). At the end of the month, Gerar acerto lists the split bills, works out the amount owed and writes a message you can copy or send on WhatsApp.

When the money arrives, it is recorded as an acerto, not as income, so your earnings stay honest. Your partner needs no account: the summary is made to be shared.

Resumo mensal Monthly summary

The year at a glance: income, expenses, settlements and the balance of each month, with a running total and a chart of the months that came out ahead or behind. Switch between Realizado (confirmed only) and Com previstos (with pending entries and the expected settlement).

Recorrentes Recurring entries

Rent, salary, the power bill: mark an entry as recorrente and the next month offers to create it again, with last month’s date and amount, for you to review before anything is added.

Patrimônio Net worth

List what you hold across banks and brokers, grouped by class or by institution. Once a month, the fechamento (closing) records your total and splits its growth into contributions and returns, so the chart shows how the portfolio moved month by month.

Prices are typed by hand. If you want, a brapi.dev token fetches quotes for ETFs and FIIs; crypto and currency stay manual.

Visão geral Dashboard

The page you land on after signing in, shown at the top of this one. It compares the month with your 12-month average, breaks spending down by category, lists what is still pending with a Confirmar button for each, and shows how much of the acerto has come in.

Your money, your server

There is no hosted version and no account to create anywhere. You run the app, and everything it knows sits in a file you control.

One container
The API and the web app ship as a single Docker image. A laptop, a home server or a small VPS will do.
One SQLite file
All data lives in /data/livro-caixa.sqlite, on a Docker volume of your own.
No outbound requests
No analytics, no trackers, no fonts from a CDN. The only call out is to brapi.dev, and only if you set BRAPI_TOKEN.
Accounts you create
There is no sign-up screen. The first user comes from the environment, more from a CLI command, and repeated wrong passwords lock the login for a minute.

Quick start

  1. Clone the repository and copy the example environment file.
  2. Set ADMIN_PASSWORD in .env: it creates the first account.
  3. Build and start the container.
  4. Open http://localhost:3000 and sign in with ADMIN_EMAIL and that password.
Terminal 
# after git clone, inside the repository
cp .env.example .env
# set ADMIN_PASSWORD in .env, then:
docker compose up --build

Behind HTTPS, set SECURE_COOKIES=true. The README lists every variable, including TRUST_PROXY for a reverse proxy.

Under the hood

A TypeScript monorepo, small enough to read in an afternoon and strict enough to change with confidence.

TypeScript, strict
Strict mode in every workspace, no any, ESLint and Prettier in CI.
Bun, Express and SQLite
Bun runs the workspaces and the server: Express 5 over bun:sqlite, with zod at every boundary.
React and TanStack Query
React 19 with Vite, Tailwind and shadcn/ui, organised by feature, with server state in TanStack Query.
Clean architecture
A pure domain package with no I/O holds the money, dates and settlement rules. Use cases depend on ports; SQLite is an adapter.
Money as integer cents
In the database, the API and the domain. Reais are formatted only at the edge, so there is no float maths on money.
Test-driven
Unit tests for the domain, integration tests for the API, component tests for the screens and Playwright for the critical flows, all in CI.

Get it running

Fork the repository and clone your fork. Then, with Bun 1.3 installed:

Terminal 
bun install
bun run seed:demo     # a year of sample data
# your dev account; it asks for a password
bun run --cwd=apps/api cli create-user you@example.com
bun run dev           # API on :3000, web on :5173
bun run test          # unit, integration and component

Work test first, one branch and one pull request per change, with Conventional Commits in English. The UI copy stays in Brazilian Portuguese, word for word from the design. The contributing guide has the rest.
